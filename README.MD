# PhotoAgent 📸

[![NET Framework](https://img.shields.io/badge/.NET-5C2D91?style=badge&logo=.net&logoColor=white)](https://microsoft.com)
[![Platform](https://img.shields.io/badge/Platform-Windows-blue?logo=microsoft)](https://microsoft.com)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**PhotoAgent** — это специализированное фоновое Windows-приложение для автоматизации процессов фотофиксации клиентов и документов с помощью внешних веб-камер. Разработано для бесшовной интеграции с внутренними CRM/ERP системами через обмен файлами (File-based API).

---

## 🚀 Основной функционал

- **Фоновый режим работы**: Приложение сворачивается в системный трей (Tray) и не отвлекает оператора до момента поступления команды.
- **Управление через JSON (File API)** — проверка папки команд каждые 500 мс, включая файлы, созданные через перенаправленный диск RDP, и задания, оставшиеся до запуска агента.
- **Интерактивный мастер настройки камер**: Удобное разделение ролей устройств (камера «Ломосдатчик» для лица и камера «Документ» для стола).
- **Полноэкранный захват поверх всех окон**: Окна съемки принудительно активируются поверх текущих окон пользователя для концентрации внимания.
- **Поддержка горячих клавиш**: Управление процессом без мыши (`Space`/`Enter` — снимок, `Esc` — отмена/выход).
- **Автоматическое обслуживание диска (архиватор)**: Ротация снимков, контроль квот хранилища (в Гб) и автоматическая очистка устаревших файлов по истечении срока хранения.
- **Автозапуск**: Самостоятельная регистрация в реестре Windows для запуска вместе с системой.

## 📁 Структура каталогов системы

При первом запуске приложение создает и использует следующую структуру папок на диске `C:\`:

```text
C:\psa_photos\
├── commands\      <- Сюда внешняя CRM кладет задания (.json)
├── responses\     <- Сюда агент возвращает отчеты выполнения (.done)
├── photos\        <- Временное хранилище текущих сессий съемки
├── archive\       <- Долговременный упорядоченный архив (по месяцам YYYY-MM)
├── logs\          <- Логи работы приложения
└── config.json    <- Файл конфигурации агента
```

## 🛠 Интеграционное API (JSON)

### 1. Запрос на запуск съемки (`commands/`)
Чтобы инициировать процесс фотографирования, создайте в папке `C:\psa_photos\commands\` файл с расширением `.json` (например, `req_101.json`):

```json
{
  "command": "capture_document",
  "request_id": "req_2026_06_10_001",
  "document_number": "4512_890432"
}
```
*Допустимые команды (`command`):* `"capture_document"` (пакет из 3-х фото: лицо, паспорт, прописка) или `"capture_extra"` (дополнительные снимки).

Агент принимает файл после двух последовательных проверок с одинаковыми размером и временем изменения, когда файл можно открыть для исключительного чтения и разобрать как полную команду. Незавершённые и занятые файлы остаются в папке для следующей попытки. В журнале появляется сообщение `Command not ready; will retry`.

Для публикации задания из 1С предпочтительно записать и закрыть файл с временным расширением `.tmp`, затем переименовать его в `.json` в той же папке. Прямая запись `.json` также поддерживается. Папку обмена должен читать клиент 1С в RDP-сеансе оператора.

Каждой новой съёмке нужен уникальный `request_id`. Завершённый запрос получает прежний результат при повторном поступлении в пределах текущего запуска агента. Ответ `.done`, оставшийся на диске после перезапуска, также предотвращает повторную съёмку. Статус `busy` допускает повторную попытку с тем же идентификатором после получения и удаления ответа.

### 2. Ответ системы (`responses/`)
После завершения сессии агент удаляет файл команды и создает в папке `C:\psa_photos\responses\` файл ответа `[request_id].done`:

```json
{
  "status": "ok",
  "request_id": "req_2026_06_10_001",
  "document_number": "4512_890432",
  "files": [
    "4512_890432_lomo.jpg",
    "4512_890432_passport.jpg",
    "4512_890432_registration.jpg"
  ]
}
```

Если оператор уже занят съемкой, мгновенно вернется статус занятости:
```json
{
  "status": "busy",
  "request_id": "req_2026_06_10_001",
  "message": "PhotoAgent is busy"
}
```

---

При отмене, таймауте или ошибке камеры возвращается `.done` со статусом `error`, идентификатором запроса и полем `message`. Обработчик ответа в 1С должен учитывать этот статус. Файл команды удаляется после публикации ответа. Ответ сначала записывается во временный файл и переименовывается в `.done` после закрытия, чтобы 1С получала целый JSON.

Окна съёмки выполняются в основном STA-потоке приложения. По истечении `captureTimeoutSec` агент закрывает окна съёмки при очередной проверке таймаута, выполняющейся каждые 5 секунд. Занятость снимается после завершения обработки.

## ⚙ Конфигурация (`config.json`)

Основные параметры работы приложения настраиваются в файле `C:\psa_photos\config.json`:

| Параметр | Тип | Описание | Значение по умолчанию |
| :--- | :--- | :--- | :--- |
| `captureTimeoutSec` | int | Таймаут ожидания действий пользователя (сек) | `120` |
| `archiveRetentionDays`| int | Срок хранения фото в архиве до удаления (дней) | `365` |
| `archiveMaxGb` | double| Максимальный размер папки архива (Гб) | `100.0` |
| `alwaysOnTop` | bool | Поверх всех окон во время съемки | `true` |

## 💻 Требования для сборки и развертывания

- **IDE**: Visual Studio 2022 / 2026
- **Платформа**: .NET Framework 4.8
- **Язык**: C# 8.0+
- **Ключевые зависимости**: 
  - `AForge.Video.DirectShow` (для работы с камерами через API DirectShow).
  - `System.Web.Extensions` (для встроенной сериализации `JavaScriptSerializer`).

### Сборка проекта:
1. Клонируйте репозиторий `https://github.com/atvrs/PhotoAgent.git`.
2. Откройте проект `PhotoAgent/PhotoAgent.csproj` в Visual Studio.
3. Восстановите NuGet-пакеты.
4. Выберите конфигурацию `Release` и нажмите **Build** -> **Publish PhotoAgent**.

Для обычной сборки без локального сертификата ClickOnce выполните `msbuild PhotoAgent/PhotoAgent.csproj /p:Configuration=Release /p:SignManifests=false /p:GenerateManifests=false` после восстановления NuGet-пакетов.

Регрессионные проверки файлового обмена запускаются в Windows командой `powershell -ExecutionPolicy Bypass -File tests/Run-CommandTests.ps1`. Для них достаточно установленного .NET Framework 4.8. Физические камеры заменяются тестовым обработчиком. GitHub Actions собирает приложение, выполняет эти проверки и сохраняет архив сборки.

Для проверки на рабочем месте запустите агент на Windows 10 и создайте задание из реальной 1С 8.2 через RDP. Проверьте открытие съёмки без перемещения файла, получение `.done`, повтор после занятого файла, отмену и таймаут. Текущий `capture_document` сохраняет три снимка с двух камер — лицо, паспорт и прописку.
